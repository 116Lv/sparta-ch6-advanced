# 01. Product Vision

## One-liner

다수 서버 환경에서도 안정적으로 동작하는 커피숍 주문 시스템을 구현한다.

## Problem

이 과제는 요구사항이 세부적으로 고정되어 있지 않다. 따라서 단순 API 구현보다 다음 질문에 답할 수 있어야 한다.

1. 포인트 충전과 차감이 동시에 발생해도 잔액이 정확한가?
2. 주문과 결제 데이터가 원자적으로 저장되는가?
3. 주문 내역을 외부 데이터 수집 플랫폼으로 전송할 때 유실과 재시도를 고려했는가?
4. 인기 메뉴 조회가 정확성과 조회 성능을 함께 고려하는가?
5. 다수 서버 인스턴스 환경에서도 같은 동작을 보장하는가?

## Target Users

- Primary user: 커피를 주문하는 사용자
- System operator: 주문 이벤트와 인기 메뉴 데이터를 운영 관점에서 확인해야 하는 사람
- Reviewer: 설계 의도, 동시성, 데이터 일관성, 확장성 판단을 평가하는 과제 리뷰어

## Product Goals

- 커피 메뉴를 조회할 수 있다.
- 사용자는 포인트를 충전할 수 있다.
- 사용자는 포인트로 커피를 주문하고 결제할 수 있다.
- 주문 내역은 데이터 수집 플랫폼으로 전송 가능한 이벤트로 남는다.
- 최근 7일 기준 인기 메뉴 TOP 3를 조회할 수 있다.
- 다수 서버 환경에서도 포인트 잔액과 주문 횟수가 깨지지 않는다.

## Non-goals

- 실제 PG 결제 연동
- 회원가입/로그인 구현
- 관리자 메뉴 관리 화면
- 재고 관리
- 주문 취소/환불
- 개인화 추천
- 실시간 대시보드 UI

## Success Criteria

- README와 docs/specs를 통해 기술 선택 이유가 설명된다.
- 포인트 변경은 동시성 전략이 명확하다.
- 주문/결제는 트랜잭션 경계가 명확하다.
- 주문 이벤트 전송은 Outbox 기반 재시도 전략이 있다.
- 인기 메뉴는 Redis 조회 성능과 MySQL 기준 복구 전략을 함께 가진다.
- 테스트 전략에 정상, 실패, 동시성, 이벤트 실패, 집계 복구 케이스가 포함된다.

## Product Principles

- MySQL을 정합성의 기준 저장소로 둔다.
- Redis와 Kafka는 성능과 비동기 처리를 위한 보조 인프라로 둔다.
- 다수 서버 환경에서 깨지는 JVM 내부 상태 기반 설계는 피한다.
- 문서 없이 구현하지 않는다.
- 검증 증거 없이 완료를 주장하지 않는다.
