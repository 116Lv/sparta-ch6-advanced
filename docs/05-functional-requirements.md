# 05. 기능 요구사항

## 기능 영역

### 1. 메뉴

사용자는 판매 중인 커피 메뉴 목록을 조회할 수 있다.

포함:

- 메뉴 ID, 이름, 가격 조회

제외:

- 메뉴 생성/수정/삭제
- 메뉴 옵션
- 재고 관리

### 2. 포인트

사용자는 포인트를 충전할 수 있다. 결제는 포인트로만 가능하다.

포함:

- 사용자 식별값 기반 포인트 충전
- 충전 이력 저장
- 동시성 제어

제외:

- 실제 PG 결제
- 충전 취소
- 포인트 만료

### 3. 주문과 결제

사용자는 메뉴를 주문하고 포인트로 결제할 수 있다.

포함:

- 주문 생성
- 포인트 차감
- 결제 기록 저장
- Outbox 이벤트 저장
- Kafka 발행 준비

제외:

- 주문 취소
- 환불
- 배송/제조 상태 관리

### 4. 인기 메뉴

사용자는 최근 7일간 인기 있는 메뉴 TOP 3를 조회할 수 있다.

포함:

- Redis Sorted Set 기반 빠른 조회
- MySQL 일별 집계 테이블 기반 복구

제외:

- 개인화 추천
- 관리자 통계 화면

## 우선순위 정의

### P0

과제 필수 요구사항이며 구현과 테스트가 필요하다.

### P1

핵심은 아니지만 설계 설명에 포함하면 좋은 요구사항이다.

### P2

추후 확장 후보이며 현재 구현 범위에서는 제외한다.

## 범위 외

- 회원가입/로그인
- 인증/인가
- 관리자 페이지
- 실제 결제 연동
- 메뉴 관리 API
- 주문 취소/환불
- 프런트엔드 UI

## 해결된 결정

- 외부 데이터 플랫폼 HTTP API는 범위 밖으로 유지한다. Kafka/Outbox 동작과 로컬 `order_paid_analytics` consumer 효과를 검증하며 별도 Mock HTTP API를 추가하지 않는다.
