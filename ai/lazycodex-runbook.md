# LazyCodex Runbook

## 이 문서의 의미

이 문서는 토큰 절약용 lazy loading 기능이 아니다. AI가 검증을 생략하거나, 증거 없이 완료를 주장하거나, 실패를 축소하는 행동을 막기 위한 검증 회피 방지 runbook이다.

문서 읽기의 기본 원칙은 다음과 같다.

> 늦게 읽고, 좁게 읽고, 작업 단계가 요구할 때만 무거운 문서를 읽는다.
>
> 늦게 읽고, 좁게 읽으며, 작업 phase가 요구할 때만 확장한다.

이 원칙은 검증 문서를 완료 단계까지 늦게 읽으라는 뜻이지, 필요한 검증을 생략하거나 약화해도 된다는 뜻이 아니다.

## 읽는 시점

다음 상황에서 이 runbook을 읽고 적용한다.

- AI가 검증 증거 없이 완료 또는 성공을 주장한다.
- reviewer가 완료 주장의 근거를 점검하거나 반려해야 한다.
- 실행하지 않은 검증, 실패 로그, API 증거, 문서 반영 여부가 누락되었다.

단순 질문, 구조 파악, 초기 계획 단계에서는 기본 필독 문서가 아니다.

## 경고 신호

- "아마 될 것입니다"처럼 추정으로 성공을 표현한다.
- 테스트를 실행하지 않았는데 완료 분위기로 답한다.
- 실패 로그나 실패 원인을 보고하지 않는다.
- 실제 API 검증 없이 controller 구현만 보고 완료한다.
- 필요한 문서 업데이트 여부를 확인하지 않는다.
- Open Question을 임의로 결정한다.
- `qa-gate`, done claim, completion checklist를 거치지 않고 완료 상태를 만든다.

## 필수 수정

이런 징후가 보이면 현재 작업에 적용되는 검증 및 완료 문서를 그 시점에 읽고 다음을 요구한다.

1. 지원되는 경로로 실제 실행한 명령과 증거를 제시한다.
2. 실행하지 않은 검증은 `NOT RUN`으로 표시한다.
3. 실패한 검증은 실패 원인과 영향을 요약한다.
4. API 변경이면 실제 request/response 증거를 제시한다.
5. 요구사항, 계약, ADR, 운영 문서의 업데이트 필요 여부를 다시 확인한다.
6. 적용되는 `checklist.md`, `ai/qa-gate.md`, `ai/done-claim-template.md`, `ai/issue-completion-checklist.md`를 완료 단계의 순서에 맞게 사용한다.

모든 문서를 한꺼번에 읽는 것이 교정 조치는 아니다. 현재 완료 주장에 적용되는 문서와 섹션만 읽되, 적용되는 gate는 빠짐없이 수행한다.

## 거부 규칙

AI가 검증 없이 완료를 주장하면 reviewer는 완료를 반려한다.

허용되는 상태:

- PASS
- FAIL
- BLOCKED
- PARTIAL

허용되지 않는 상태:

- "거의 완료"
- "테스트는 안 했지만 괜찮음"
- "코드상 문제 없어 보임"
- 증거 없는 `DONE` 또는 완료 주장
